# Modello: il brief di un thread

Quello che il coordinatore scrive quando apre un lavoro in parallelo. Un thread che sa solo «fai il menù»
rifà cose già decise o pesta i file di un altro (lezione L15).

```
Obiettivo: cosa deve esistere alla fine, in una frase dal lato di chi gioca.

Decisioni che valgono: D0xx, D0yy (da DECISIONI.md). Non riaprirle.
Decisioni ancora aperte che ti toccano: ... (se ce n'è una di fondazione, aspetta).

Contratto: i dati o le interfacce che leggi e quelli che produci (file, formato, chi li consuma).
File di tua proprietà: ... . File di altri che non tocchi: ... (risorse in produzione.yaml).

Custodi: il custode visivo approva ogni grafica nuova; il custode di trama e nomi ogni battuta, nome o
luogo nuovo. Niente trama a Cioti.

Criterio d'uscita: le prove che devono passare (python3 tools/prove.py --tutte, prove mGBA, grafo della
trama a 0 errori, controlla_metodo a 0 errori) e cosa si mostra a Cioti.

Dopo: il pezzo successivo in coda, così non resti fermo a fine lavoro.

Metodo: ogni decisione nuova va in docs/metodo/DECISIONI.md, ogni rifacimento in LEZIONI.md, nella
stessa fusione.
```
